# Орбита — визуальная доска Singularity

Локальное приложение для одного пользователя: свободная доска с четырьмя настраиваемыми квадрантами, задачами и сценариями. Java 21 / Spring Boot 3.5.3, PostgreSQL / Liquibase, React 18 / TypeScript / Vite / React Flow. Интерфейс на русском языке.

Для начала нового чата и знакомства с реализацией: [контекст проекта](docs/PROJECT_CONTEXT.md) — поведение приложения, источники данных, карта кода, правила сохранности и известные ограничения.

## Запуск на Fedora через Docker Compose

Нужны работающий Docker Engine или Docker Desktop и команда `docker compose`. Выполняйте из корня репозитория:

```bash
# Существующий .env с токеном не перезаписывается.
test -f .env || cp .env.example .env
APP_MODE=demo docker compose up --build -d
docker compose ps
xdg-open http://127.0.0.1:8080
```

Новая демонстрация содержит 14 задач и 4 сценария в ветках «Цели» и «Опасения», включая задачу с несколькими сценариями и обычными тегами. Ранее сохранённые демоданные не перезаписываются. Изменения демоданных сохраняются в БД. Режим demo не обращается к Singularity даже при наличии токена.

```bash
docker compose logs --tail=100 app
docker compose stop                 # остановить, сохранив данные
docker compose up -d                # продолжить в режиме из .env
```

На хост публикуется только приложение: `127.0.0.1:8080`. PostgreSQL доступен контейнеру приложения по `db:5432` внутри сети Docker; занятый порт `5432` на Fedora запуску не мешает. База хранится в именованном томе `singboard_board-db`. Не используйте `docker compose down -v`, если нужны сохранённые данные.

Если контейнер БД был создан прежней конфигурацией с публикацией `5432`, повторите `APP_MODE=demo docker compose up -d` (или `APP_MODE=real` для реального аккаунта): Compose пересоздаст контейнер с новой конфигурацией, сохранив том БД. Пересборка образа для этого изменения не нужна. Открывайте браузер после успешного запуска контейнеров.

## Подключение реального аккаунта

В `.env` должна быть строка `SINGULARITY_API_TOKEN=...`. Токен передаётся только backend; он исключён из Git, Docker build context и frontend. Доступ REST API зависит от тарифа Singularity.

```bash
APP_MODE=real docker compose up -d --force-recreate app
xdg-open http://127.0.0.1:8080
```

В шапке появится «реальный аккаунт». Настройки → корневой тег: выберите существующую ветку «Проекты доски» или явно создайте новый корень, дождитесь операции и выберите его. Внутри корня используются две ветки:

```text
Проекты доски
├── Цели
│   └── Желаемый сценарий
└── Опасения
    └── Нежелательный сценарий
```

Ветки с точными именами «Цели» и «Опасения» распознаются при синхронизации, если каждая встречается под корнем ровно один раз. Можно выбрать ветки вручную в настройках; после выбора сохраняются их ID, поэтому переименование не меняет тип сценариев. Если веток нет, создайте их явными кнопками в настройках после сохранения корня. Запуск и чтение сами теги не создают. Корень и две ветки служат группами и не показываются карточками.

Сценариями становятся потомки этих двух веток, включая вложенные теги. Старые теги вне групп остаются серыми карточками «Без группы»; перенесите их в нужную ветку в Singularity, чтобы задать тип. ID, связи задач, скрытие и сохранённая раскладка остаются прежними. Теги и задачи не удаляются и не перемещаются автоматически в Singularity. Отдельной сущности «проект доски» нет; родные проекты Singularity сохраняют своё назначение.

Удалённые или недоступные теги не показываются на полотне и в боковом списке. Действующие сценарии остаются видимыми, даже если с ними не связано ни одной задачи; новый сценарий появляется сразу после создания. Кэш и сохранённая раскладка сохраняются; если выбранный сценарий удалён во внешней системе, его фильтр сбрасывается.

Возврат к деморежиму: `APP_MODE=demo docker compose up -d --force-recreate app`. Для постоянного выбора запишите `APP_MODE=real` или `APP_MODE=demo` в `.env`. Настройки, кэш и раскладка режимов изолированы в одной БД.

## Сборка и разработка без контейнера приложения

```bash
sudo dnf install java-21-openjdk-devel nodejs npm python3
sudo npm install --global yarn@1.22.22
export JAVA_HOME=/usr/lib/jvm/java-21
export PATH="$JAVA_HOME/bin:$PATH"
./scripts/build.sh
```

Нужен Node.js 22.12+; версии frontend зафиксированы в `frontend/yarn.lock`. Maven 3.9.12 загружается Wrapper автоматически. Сборка сначала создаёт frontend, затем включает его в исполняемый JAR и запускает backend-тесты.

Для разработки с PostgreSQL:

```bash
docker compose -f compose.yaml -f compose.dev.yaml up -d db
DB_URL=jdbc:postgresql://127.0.0.1:15432/singboard ./mvnw spring-boot:run
# В другом терминале:
cd frontend
yarn dev
```

Frontend: `http://127.0.0.1:5173`, proxy `/api` → `127.0.0.1:8080`. Backend: `http://127.0.0.1:8080`. Дополнительный файл `compose.dev.yaml` публикует БД только на `127.0.0.1:15432`; он нужен для backend вне Docker. Если этот порт тоже занят, измените его в дополнительном файле и в `DB_URL`. Для нестандартных реквизитов БД передайте `DB_URL`, `DB_USER`, `POSTGRES_PASSWORD` в окружении backend.

Дополнительный вариант без Docker/PostgreSQL — локальный профиль с файловой H2, теми же миграциями и сохраняемой базой `data/singboard.mv.db`:

```bash
APP_MODE=demo ./scripts/run-local.sh
# Реальный режим: скрипт безопасно читает только SINGULARITY_API_TOKEN из .env.
APP_MODE=real ./scripts/run-local.sh
```

JAR должен быть предварительно собран. Сам Spring Boot не загружает `.env`: это делает Docker Compose или `run-local.sh`. Не передавайте токен параметром командной строки.

## Как пользоваться

- «Все задачи» открывает общий список: размещённые, неразобранные и скрытые задачи, поиск и страницы по 20 строк. Нажмите название для свойств; ↗ приближает размещённую карточку, размещает неразобранную или возвращает скрытую. Выбор сценария и поиск по полотну сбрасываются; область родных проектов и переключатель «Показывать выполненные» учитываются. Повторяющиеся серии показаны одной строкой.

- Введите название в нижнее поле и нажмите Enter. Двойной щелчок по свободному полотну создаёт задачу в выбранной точке. Если выбрана цель или опасение, новая задача сразу получает тег сценария. Его название видно над полем быстрого ввода и в диалоге создания на полотне.
- Новые внешние задачи появляются в отдельной панели «Неразобранное»: поиск, страницы по 20 задач и собственная прокрутка. Выберите в списке «Разместить в» нужный квадрант и нажмите ↗ — карточка займёт свободное место без перемещения остальных задач. Можно оставить «Текущий вид» или перетащить строку на точное место. Пока задача не размещена, она не занимает место на полотне и не уменьшает масштаб при «Показать всё».
- Карточки можно двигать; у выбранной карточки доступны маркеры изменения размера. Обычное колёсико меняет масштаб, дополнительное горизонтальное колёсико сдвигает полотно влево/вправо; Shift + колёсико также сдвигает его горизонтально. Масштаб, положение просмотра и раскладка сохраняются с задержкой 450–600 мс.
- Матрица автоматически расширяется наружу, когда размещённая карточка приближается к внешнему краю. Пересечение осей фиксировано; координаты, размер карточек и масштаб камеры сохраняются. Размещение по квадрантам заполняет компактную сетку и при необходимости добавляет место.
- Цвета квадрантов: сверху слева серый, сверху справа зелёный, снизу слева розовый, снизу справа светло-персиковый; каждый обведён сплошной рамкой.
- Потяните ручку на внешней границе для ручного изменения размера. Можно выделить её клавишей Tab и использовать стрелки; Shift увеличивает шаг. Сжатие сохраняет место для уже размещённых карточек.
- Размер матрицы сохраняется в БД. Скрытие/перенос задач оставляет свободное пространство; кнопка «Подогнать границы» убирает его явно. Для работы с частью большой доски выберите квадрант в списке «Приблизить» или нажмите ↗ в его заголовке.
- Выберите цель или опасение на доске или в списке слева, чтобы выделить сценарий и связанные задачи. Остальные карточки приглушаются. Щёлкните по свободному месту или нажмите «Показать всё», чтобы снять выделение и вернуть полную контрастность. Поиск и переключатель выполненных фильтруют карточки.
- Для нового сценария выберите «Цель» или «Опасение» под списком слева, введите название в отдельное поле и нажмите Enter либо «Добавить цель/опасение». Во время отправки повторное нажатие заблокировано; после принятия запроса появляется сообщение об очереди. Ошибка показывается рядом с формой, введённое название сохраняется. Если нужная ветка отсутствует, удалена или перемещена из корня, форма объясняет причину и открывает настройки.
- Соедините правую точку задачи с точкой сценария, чтобы добавить его тег. У цели точка находится слева, у опасения — сверху. Цель соединяется зелёной линией с треугольным наконечником от задачи к сценарию; опасение — красной линией с круглым окончанием у сценария. Выберите линию → «Убрать связь», чтобы снять только этот тег. Те же связи доступны флажками в свойствах задачи: «Помогает достичь» и «Помогает предотвратить». Одна задача может иметь оба типа связей и свободно находиться в любом квадранте.
- Карточки целей обозначены зелёным цветом и значком ◎ и находятся за правой границей матрицы; опасения — красным цветом и значком ! и находятся под нижней. Их можно двигать вдоль соответствующей стороны и дальше наружу. При расширении матрицы сценарии остаются снаружи; задачи не перемещаются из-за типа связей. Префиксы к названиям не добавляются.
- Свойства задачи: название, описание, отдельные начало и крайний срок, выполнение. Отправляются только изменённые поля. Обычные описания редактируются текстом; форматированные — как Quill Delta JSON, с явным действием для замены простым текстом.
- Скрытие карточки не удаляет задачу. Список «Скрытые карточки» возвращает её в прежнее положение.
- Рядом со «Скрыть с доски» есть «Удалить задачу» с красной корзиной. После подтверждения запрос попадает в очередь. Успешное удаление навсегда убирает задачу из Singularity, с полотна и из списков. Singularity может удалить и её подзадачи.
- Сверху и слева от матрицы расположены прямоугольные блоки с общим вопросом и двумя подписями направлений. Подписи набраны крупным жирным шрифтом. Их текст и названия квадрантов редактируются в настройках. Там же задаются часовой пояс, интервал обновления 15–3600 секунд и область по родным проектам Singularity. Изменение настроек не сдвигает карточки.
- Экземпляры одной повторяющейся серии представлены одной карточкой с маркером «Повторяется». Доска показывает самый ранний незавершённый экземпляр. Флажки в свойствах и линии на полотне добавляют и снимают теги сценариев на шаблоне серии. Связи, положение и размер карточки сохраняются при смене экземпляра. Разные задачи с одинаковым названием не объединяются. Полный набор экземпляров остаётся в кэше.
- Окно операций показывает очередь, отправку, ошибки и конфликты с тремя значениями: исходным, внешним и вашим. Ошибка одной задачи блокирует её следующие операции до решения, остальные задачи продолжают обрабатываться.

### Дерево целей и опасений

В настройках включите «Показывать вложенность тегов как связи сценариев». Предпросмотр показывает, какие стрелки появятся из существующих вложений Singularity. Две подцели «Продать квартиру в городе» и «Найти подходящий посёлок» можно вложить в «Переехать жить за город». Задаче достаточно тега любой из трёх целей.

На доске выберите подцель и нажмите «Ведёт к цели…». Для опасения доступна команда «Ведёт к риску…». Выбор «Без родительского сценария» переносит тег на верхний уровень его ветки. То же действие есть на выбранной стрелке. Изменения, сделанные перетаскиванием тегов в Singularity, появляются после очередного обновления. Выбор общей цели подсвечивает и её потомков, и их задачи. Переключатель «Только цели и опасения» оставляет на полотне сценарии и стрелки между ними.

### Цепочки задач

В настройках выберите тег цепочек, например «Цепочка», вне корня сценариев. Если такого тега ещё нет, создайте его кнопкой, дождитесь появления в списке, выберите и сохраните настройки. В новой демобазе тег уже выбран.

- Чтобы соединить две размещённые задачи, потяните правую точку первой к синей точке слева у второй. Две разовые задачи без родителя и без проекта Singularity сразу соединяются пунктирной синей стрелкой в Орбите.
- Для двух разовых задач без родителя из одного проекта и раздела откроется форма с порядком шагов. Кнопка «Связать только на доске» сохраняет пунктирную стрелку в Орбите. Кнопка «Создать цепочку в Singularity» после ввода названия создаёт общую родительскую задачу. Если тег цепочек ещё не выбран, форма откроет его настройку и сохранит выбранные шаги.
- Чтобы удалить пунктирную стрелку, выберите её и нажмите «Убрать связь». Если Singularity отклонил добавление первого шага новой цепочки, действие «Связать только на доске» в панели цепочки и в операциях синхронизации сохранит стрелку и закроет обе операции добавления шагов. Если для одной из карточек уже ожидает удаление, отмените его перед сохранением стрелки.
- Тем же жестом можно вставить свободную задачу до или после шага цепочки в проекте либо поменять порядок внутри одной цепочки. Готовую карточку без проекта можно соединить пунктирной стрелкой и с уже существующим шагом без проекта.
- В разделе «Цепочки» нажмите «Создать цепочку», введите название и выберите проект Singularity. Орбита создаст родительскую задачу с тегом цепочки. В Singularity цепочку можно завести тем же способом вручную и добавить ей подзадачи.
- В списке шагов можно создать новую подзадачу, в том числе у цепочки без проекта. Для цепочки в проекте можно выбрать существующую задачу без родителя из того же проекта и раздела. Поле «Вставить шаг после» задаёт позицию, кнопки ↑ и ↓ меняют порядок. При ошибке прежней операции панель называет её и открывает список операций. Чтобы вынести шаг из цепочки, измените его вложенность в Singularity.
- Выбор цепочки подсвечивает её карточки, синие стрелки и первый незавершённый шаг. Завершённые шаги остаются видны в фокусе. Неразмещённый шаг можно отправить на доску кнопкой ↗. Каждая карточка сохраняет свои сроки, теги и раскладку.

В этой версии у подцели один родитель в своей ветке, у шага одна цепочка. Стрелка между шагами передаёт очерёдность подзадач. Автоматический перенос дат и связи Ганта в контракт синхронизации не входят.

## Данные и синхронизация

Задачи и обычные поля принадлежат Singularity. Сценарии соответствуют тегам по ID, их вложенность задаётся полем `parent`. Для синхронизируемых цепочек используются `parent` и `parentOrder` подзадач. Локальная БД хранит раскладку, стрелки со связями на доске, настройки, кэш и очередь операций. Связи задач со сценариями меняют теги и сохраняют родные проекты Singularity.

Загрузка выполняется при запуске, по таймеру и кнопке, с полной сверкой всех страниц. Для задач используется `includeAllRecurrenceInstances=true`, исключающий документированные пропуски offset-пагинации. Для первой версии выбран полный опрос; `modifiedSince` не используется. Область проектов применяется к представлению, полный кэш сохраняется.

Перед записью тега backend заново читает задачу и меняет конкретный ID, сохраняя прочие теги. После PATCH сверяет результирующий набор. Исходящие изменения сериализованы; без подтверждённой условной записи API остаётся окно гонки между чтением и записью. После сетевых ошибок безопасные изменения получают до трёх попыток с задержкой и учётом `Retry-After`. Чтение после ошибки повторяется следующим циклом с увеличением интервала.

Операция сохраняется до отправки. Повтор запроса быстрого ввода с тем же `requestId` возвращает ту же операцию, включая случай потери HTTP-подтверждения. После неоднозначного создания POST не повторяется. Задачу можно сверить по `externalId`; ноль или несколько совпадений не считаются доказательством успеха. Создание тега после тайм-аута проверяется вручную. После аварийного завершения отправлявшиеся создания переходят в «Результат неизвестен».

## Проверки

```bash
./mvnw verify                         # backend + тесты с локальным HTTP-сервером
cd frontend
yarn build                           # TypeScript + production bundle
yarn format:check                    # форматирование исходников
yarn test:unit                       # независимые проверки обработки данных UI
yarn playwright install chromium     # однократно
# Перед E2E соберите JAR из корня: ./mvnw package -DskipTests
yarn test                            # сценарии с собственным demo backend на 18080
```

Для системного Chrome на Fedora: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/google-chrome yarn test`. E2E используют отдельную H2 в памяти и никогда не читают `.env` или реальный аккаунт. Проверки HTTP-клиента используют только поддельный сервер/транспорт. Для среды, запрещающей TCP-сокеты: `./mvnw verify -DexcludedGroups=network`; это сокращённая проверка, которая не заменяет полный прогон.

Фактические результаты и ограничения среды записаны в [docs/verification.md](docs/verification.md).

## Резервные копии

```bash
./scripts/backup.sh
# Восстановление заменяет текущую БД; приложение временно останавливается:
./scripts/restore.sh backups/singboard-YYYYMMDD-HHMMSS.dump
```

Копия содержит настройки, раскладку, демоданные, кэш и очередь. Токен не хранится в БД; сохраните `.env` отдельно безопасным способом. Для H2 остановите приложение и скопируйте весь каталог `data/`. Из одних тегов Singularity положение карточек восстановить нельзя.

## Ограничения первой версии

Один пользователь и одна доска, без публичной авторизации. Не публикуйте приложение в интернете. Связи повторяющихся задач редактируются на доске при доступном шаблоне серии, а их поля и удаление — в Singularity. Зашифрованные задачи можно читать и перемещать на доске. В real снятие существующей даты отключено до подтверждения семантики API; снимайте дату в Singularity. Даты со временем вводятся как ISO 8601 со смещением, без автоматического преобразования календарного дня. Богатое описание редактируется через Delta, полноценный визуальный rich-text редактор пока не включён.

После обновления старый масштаб просмотра сохраняется. Если ранее вся доска уменьшилась из-за длинного списка, один раз нажмите «Показать всё» — теперь в расчёт входят только матрица, размещённые карточки и сценарии.

Официальные источники и принятые ограничения адаптера: [docs/api-notes.md](docs/api-notes.md).
