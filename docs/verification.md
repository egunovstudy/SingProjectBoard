## Не удалось проверить в этом окружении

- **8 тестов на настоящем локальном поддельном HTTP-сервере:** создание TCP-сокета завершается `java.net.SocketException: Operation not permitted`. Они помечены `network`, присутствуют в исходниках и включены по умолчанию.
- **Запуск веб-сервера из JAR:** Spring и миграции запускаются, но Tomcat не может привязать локальный сокет по той же причине. Это не успешный запуск приложения.
- **6 Playwright E2E:** `yarn test` завершился до сценариев, так как собственный backend не смог стартовать. Независимая попытка запуска Chrome также завершилась на `setsockopt: Operation not permitted`. Скриншоты и визуальное прохождение не подтверждены.
- **Docker Compose / PostgreSQL / резервная копия:** Docker socket возвращает `permission denied`. Образы не собирались, контейнеры и восстановление `pg_dump` не проверены. SQL-миграции выполнены на H2 в режиме совместимости с PostgreSQL.
- **Реальный Singularity:** DNS для `api.singularity-app.com` недоступен из shell. Официальная схема изучена через инструмент документации, но токен пользователя и запись в аккаунт не проверялись. Демо и поддельный транспорт не считаются подтверждением реальной интеграции.

Запрос расширенных сетевых прав отклонён политикой окружения. Внешние ограничения не обходились.

## Оставшиеся функциональные ограничения

Повторяющиеся/зашифрованные задачи редактируются только в Singularity. В real отключено снятие даты до подтверждения API. Форматированное описание редактируется как Quill Delta, без визуального rich-text редактора. Синхронизация — периодический полный опрос; фильтр родных проектов ограничивает отображение, а не объём загружаемого кэша. Без условной записи API остаётся окно гонки между свежим чтением и PATCH. Первая версия требует полного E2E и реального API-прогона на машине без указанных ограничений.
